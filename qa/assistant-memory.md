# 手动记忆端到端验证

使用仅监听回环地址的独立 API、数据库和 Redis。开启临时环境的 assistant、独立删除日志和 `assistant.memory.enabled`。初始化的删除日志应位于数据库备份目录之外。测试全程使用合成文本。

| 模式 | 命令 | 验证内容 |
| --- | --- | --- |
| 常规 | `node qa/assistant-memory-smoke.mjs http://127.0.0.1:18105 normal` | 默认关闭，拒绝写入，显式同意后找不到被拒绝的条目。验证范围隔离、独立设置、分页、Unicode 上限、编辑权限和并行替换、关闭时删除、重新启用后的单条撤权和账号注销。 |
| 关闭 | `node qa/assistant-memory-smoke.mjs http://127.0.0.1:18105 disabled` | 运行在记忆功能关闭的独立 API，验证能力状态与接口拒绝。 |
| 备份恢复 | `node qa/assistant-memory-smoke.mjs http://127.0.0.1:18105 restore <空证据目录>` | 从撤权前的备份启动，验证设置撤权、单条删除和旧版本撤权都会重放。备份中的有效版本仍可读取。重新手动启用后，新设置生效，已删除和替换的旧条目仍不可见。 |

备份恢复模式通过证据目录内的文件与数据库恢复流程同步。

1. 等到 `backup-ready.json` 写好，对当前独立数据库做快照，然后创建 `backup-done.json`。
2. 等到 `restore-ready.json` 写好，停止该 API。将快照恢复到第二个独立数据库，并沿用原来的删除日志和日志身份。
3. 让同一回环端口重新提供服务，确认日志恢复完成后创建 `database-switched.json`。
4. 等待脚本通过并写出 `summary.json`。证据文件只包含合成数据的 ID 和通过状态。

关闭某个记忆范围会隐藏现有条目并拒绝新增或编辑。用户重新同意后，可读取该范围中仍未单独删除的条目。修改条目正文会返回新 ID 并撤销旧 ID。重复提交相同正文保持原 ID。历史引用与自定义指令各自保存。以上测试验证记忆、设置和撤权 API。普通聊天中的上下文引用与来源展示另有验收。
