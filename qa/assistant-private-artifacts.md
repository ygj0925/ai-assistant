# 私有文稿、版本与文本下载

在具有独立删除日志的消费者后端启用 `assistant.artifacts.enabled=true`。功能探测返回 `private_artifacts`。登录后在工作空间使用 `/api/assistant/v1/artifacts`，创建时发送 UUID 格式的 `Idempotency-Key`。 [独立删除日志](assistant-erasure.md)

- 从本人项目创建空白或已有文本的文稿，或选择本人一次已完成运行的回复，原样复制其文本。回复的项目归属自动确定。文稿固定绑定其创建时的所属项目和来源回复，历史与下载仍校验所选工作空间、所有者、项目及来源会话。
- 列表和版本历史只读取轻量元数据。每次保存需提交当前 `baseVersionId`，两个使用同一基础版本的并行保存只接受一次。回滚复制所选历史内容并产生新版本，保留回滚前后的历史。
- 文稿按 UTF-8 实际长度校验。每篇最多 32 KiB，每个文稿保留 32 个版本，每位所有者在一个工作空间中最多 64 篇。普通文本和 Markdown 分别以固定 `artifact-<版本号>.txt` 和 `artifact-<版本号>.md` 文件名返回。草稿标记保持原始字节，浏览器下载使用 MIME 校验和沙箱限制。 [私有工作表与 XLSX](assistant-spreadsheet.md) · [私有演示稿与 PPTX](assistant-presentation.md) · [私有代码稿](assistant-code-draft.md) · [私有静态网页](assistant-webpage.md)
- 文稿删除先记录独立撤回，再删除历史。删除来源会话或注销账号也移除关联文本。备份恢复时先重放撤回，并重新验证来源。已撤回文稿的相同创建键无法恢复原对象。

## 复跑

在本机隔离 PostgreSQL、Redis 和独立删除日志上启动打包 API，启用测试注册、合成模型和任务执行。脚本使用现建模拟账号与合成内容，通过回环进行网络访问。

```powershell
node qa/assistant-private-artifacts-smoke.mjs http://127.0.0.1:18128
```

恢复用例需要同一独立日志绑定的两个隔离数据库。脚本创建测试数据后写入 `backup-ready.json`，此时对原测试库执行 `pg_dump`，完成后写入 `backup-done`。脚本随后分别撤回来源会话、已经存在的文稿，以及在备份后创建的文稿，并写入 `deletion-ready.json`。停止原测试服务，从备份恢复新测试库，用同一独立日志启动新服务。服务启动、迁移和撤回重放完成后，于证据目录写入 `restore-done`，脚本继续核验恢复后的下载和同键重试。

```powershell
node qa/assistant-private-artifacts-smoke.mjs http://127.0.0.1:18128 --replay <隔离证据目录> http://127.0.0.1:18129
```

MySQL 8.4.11 使用关闭 TCP 的命名管道测试库验证增量脚本。新增两表，原三条检索目录记录保留。事务确认中文、emoji 与 CRLF 的 12 字节原样存储，删除文稿时级联移除历史，`ARTIFACT` 事件类型可落库，伪造源会话归属触发外键拒绝，HTML 格式触发约束拒绝。测试回滚后文稿表无测试数据。

2026 年 11 月 24 日，完整 Maven 验证通过。打包 API 在隔离 PostgreSQL 新库执行 110 项变更集，对恢复库确认 110 项已执行和零项新增。实际 HTTP 回归验证了回复提取、并发保存的 201 与 409、三个留存版本、跨账号及游标拒绝、32,768 字节边界、第 33 版被拒绝与注销后访问失效。生产前端的 Chrome 回归完成了创建、编辑、回滚到第 3 版、下载原始 Markdown 与删除后的目录检查。

恢复回归使用同一独立日志。删除来源会话、删除已有文稿及在备份后创建并删除文稿的三种撤回均经重放保持生效。原始创建键无法恢复这些文本，仍保留的文稿可按原样下载。原有的两页个人数据导出自测也在恢复后的 API 上通过。 [个人数据导出](assistant-privacy-export.md)

严格声明只接受普通文本或 Markdown 的下载请求也完成权限回归。匿名请求返回 401，其他账号与已撤回来源返回 404，错误响应明确使用 JSON 与 `no-store`。成功下载仍保留原始字节和文本媒体类型。
