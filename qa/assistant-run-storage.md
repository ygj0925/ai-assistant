# 运行和账本迁移验证

2026 年 11 月 22 日，在独立 MySQL 8.4 和 PostgreSQL 16.15 实例中，按账号、会话、消息节点、运行的顺序执行迁移 SQL。四组迁移和以下数据检查均通过。

- 两个账号可使用相同的幂等键摘要。同一账号重复写入该摘要时，数据库拒绝写入。
- 运行关联到指定账号和工作空间的会话。跨工作空间绑定会话、绑定其他会话的提示消息和写入非法运行状态均被拒绝。
- 运行可从排队推进到完成，保留输出及回复节点引用。清理事件后，最早可读序号为 `3`，最后已写入序号仍为 `2`。
- 额度可原子地从预留转为已用。超额度预留、将费用关联到其他账号及同一运行重复计费均被拒绝。
- 订阅回调可以先于订单入库，随后绑定同渠道订单。重复回调和跨渠道绑定订单均被拒绝。

订阅部分验证了数据库约束。渠道签名校验、到账和退款行为由支付沙箱用例验证。

在同日使用正式打包产物的 PostgreSQL 主变更清单，在隔离空库中执行首条变更、升级至当前版本、重复执行。变更历史数量为 `1 → 35 → 35`，应用角色无需数据库超级用户权限，默认运营管理员仅存在一条。 [迁移探针](ContiNewMigrationProbe.java)

最新打包版在另一套 PostgreSQL 空库执行首条、全量和重复迁移，最终再次得到 `1 → 42 → 42` 个变更集。
