# 合成工作区的资格和监护授权

监护试点只作用于部署中明确配置的一个合成工作区。操作者为两个已经存在的测试账号建立关系。服务端不接收出生日期、年龄证明、真实地区、监护凭据或联系方式。地区不符是独立的测试场景。个人工作区及其他工作区保持原有功能权限。

- `assistant.eligibility.enabled` 默认关闭。`assistant.eligibility.fixture-workspace-id` 指定试点工作区。配置试点后，缺少有效登记的账号无法执行试点连接器动作，关闭操作入口后该限制继续生效。
- ContiNew 操作者使用 `assistant:eligibility:provision` 权限和分配到该工作区的决策权限。服务端核对两个账号的当前确切成员资格，拒绝以同一身份自授权。操作者、参与账号和监护账号使用各自的身份令牌。
- 账号读取 `GET /api/assistant/v1/eligibility` 获取当前范围的状态和拒绝原因。监护者读到的回执只有不透明登记 ID、确切同意版本、状态和适用时的过期时间。用本人会话、当前版本和明确确认调用 `PUT /api/assistant/v1/eligibility/guardian/consents/{id}` 批准或撤回。重复批准当前有效版本会保留原过期时间。
- 试点只对本地连接器模拟器应用该同意。授权、创建请求、审批、从持久队列调度和接受模拟凭据时均校验资格。动作保存确切同意版本，撤回、过期或重新批准后不会恢复旧审批。历史状态和结果仍可查看。
- 独立日志退役确切同意版本。恢复旧库时，已经撤回的同意无法重新生效。成员退出或删除账号会清理关系和审计记录，重新加入不能恢复旧关系。真实外部连接器、年龄核验、适用市场和生产专项入口属于具体发布依赖。

## 本地验证

`qa/assistant-guardian-eligibility-smoke.mjs` 使用合成身份、真实本机 ContiNew 会话、隔离模拟账本和 PostgreSQL 16 的两份恢复样本。测试从已配置试点但尚未登记时及已经批准后分别备份。

- PostgreSQL 16 新库应用 170 项 Liquibase 变更。两份备份分别恢复到独立数据库并保留同一日志和账本，各次启动迁移零项。验证确切同意、实际到期、真实本地凭据、旧动作与提醒被拒绝、撤回前备份仍保持撤回、监护者退出后重新加入仍保持限制，以及关闭入口后恢复登记前备份仍拒绝访问。普通个人空间仍可执行并取得本地凭据。[HTTP 和备份恢复](verify-results/guardian-eligibility-2026-11-24/replay.log)
- 生产 Web 构建用 Chrome 验证独立 ContiNew 运营身份实际登记、监护者明确授权、参与者与监护者独立会话、连接器入口变化及监护者撤回。[浏览器验证](verify-results/guardian-eligibility-2026-11-24/browser.log)
- MySQL 8.4 禁用网络的命名管道应用四项配对迁移。插入并撤回同意及验证动作版本的过程在事务中回滚。自授权、地区不符条件下的活动同意、非法动作版本均返回约束错误。删除关系会级联清理审计，既有检索目录三行保持原样。[原生迁移](verify-results/guardian-eligibility-2026-11-24/mysql.log)
