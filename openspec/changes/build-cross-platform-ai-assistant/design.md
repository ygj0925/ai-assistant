## Context

AI 助手在独立工程内开发。前期调研借鉴了 Guard Find 的 Expo/RNOH 构建链路和后台流式聊天。产品以独立克隆的 ContiNew Admin 为后端底座，使用独立身份、对象存储、数据库、计费、发布与运维边界。对标状态随地区、套餐、平台、渠道和灰度变化。上线判断依赖真机、供应商、商店和故障演练证据。 [技术调研](../../../docs/architecture/技术架构与工程边界.md) · [二次审查](../../../docs/release/后端选型与功能复审.md)

## Goals / Non-Goals

**Goals**

- 将公开功能目录转化为跨端契约、逐阶段可运行的产品以及可复现的自测。
- 支持 Web、iOS/iPadOS、Android、HarmonyOS NEXT、macOS 和 Windows 的核心旅程。高级能力按市场、套餐、平台和权限逐项启用。
- 以账号、工作空间、区域和数据用途为基本隔离边界。保留供应商切换、客户端兼容和数据恢复能力。

**Non-Goals**

- 产品采用自有设计系统、品牌和文案。模型质量用任务题集衡量。
- 独立浏览器产品、独立视频产品、广告、特定合作渠道、行业专用产品、Linux 原生与微信小程序进入待决策清单。Linux 首发使用 Web。

## Decisions

### 工程结构与客户端

以下路径均相对于独立的 AI 助手项目根目录。后端、规划与验收目录已存在，客户端和基础设施目录随对应实施任务创建。

```text
ai-assistant/
├─ docs                产品规划、架构和发布审查
├─ openspec            变更与验收规范
├─ clients/web         浏览器端，Next.js 与 React
├─ clients/mobile      iOS、iPadOS、Android，React Native 与 Expo
├─ clients/harmony     HarmonyOS NEXT，M0 选择 RNOH 或 ArkTS/ArkUI
├─ clients/desktop     macOS、Windows，Electron 宿主与共享渲染组件
├─ packages/           API/事件契约、SDK、设计变量和测试数据
├─ services/api        独立 Git 仓库，ContiNew Admin 与 AI 产品模块
├─ services/worker     持久化任务消费与模型/工具编排
├─ infra/              各环境部署、迁移、观测和发布配置
└─ qa/                 数据夹具、真机矩阵、评测和演练记录
```

共享业务协议和设计变量可保持语义一致，同时允许编辑器、系统分享、键盘、权限和购买使用端侧组件。全端共用 UI 的方案维护成本取决于原生边缘能力，M0 先用鸿蒙录音、SSE、输入法、签名、推送和商店联调验证。Electron 的 Chromium 版本一致性适合复杂编辑器。体积或内存超出 M0 基线时，用同样的媒体与编辑器用例评估 Tauri。桌面宿主隔离渲染内容，IPC 按动作授权，外部内容在隔离环境中打开。

### ContiNew Admin 接入

基线为 `v4.2.0`，本地分支 `codex/ai-assistant-backend`，起始提交 `6c6724e4444268b81e27442abb93252d3bfc2bd6`。底座为 Java 17 / Spring Boot 3.5 系列。用 `continew-server` 启动与打包，评估复用 `continew-system` 的运营身份、RBAC、文件及审计基础，以及 `continew-plugin-tenant` 的租户能力。将 AI 业务放在独立 Maven 模块，例如 `continew-assistant`，通过根 POM 模块列表与依赖管理注册。Worker 与 API 通过持久化运行契约衔接。

管理 API 和消费者 API 使用不同访问策略、令牌用途、路由和权限。租户请求头只用于选择目标，服务端用登录主体和资源归属查证其成员关系。对缓存、数据库、对象存储、SSE、队列和异步 Worker 逐层传递、校验工作空间上下文。公开环境从网络和权限侧保护后台接口，审查默认账号、演示配置、文档/生成器入口和异常日志，若不在产品范围则关闭。

上游自带 MySQL 与 PostgreSQL SQL，当前标签的默认主 changelog 启用 MySQL。M0 用隔离 PostgreSQL 和 Redis 验证空库初始化、连续迁移、默认租户及 RBAC、连接池与 Worker 事务；后续按仓库约定维护双数据库迁移文件，发布以目标数据库实测为准。核对上游后续 RSA 初始化修复是否适用于 v4.2.0，先复现登录路径和启动行为，再为所选版本处理。业务模块避开通用 CRUD 对 SSE 的响应包装，测试反向代理和客户端缓冲。

后端目录作为独立 Git 工作树维护。正式协作前确定团队自己的后端远端，并约定父仓如何锁定后端版本及 CI 如何检出。上游地址作为后续比较与更新的来源。

### 接口、数据与跨端恢复

先冻结 API 版本、资源标识、错误码、分页、功能资格解释和事件格式，再生成或手写各端 SDK 并运行契约测试。登录按客户端发行渠道选安全的认证方式，服务端每次访问校验区域、工作空间、用户、资源权限与套餐；端侧只作适配和反馈。

PostgreSQL 持有用户、工作空间、项目、会话、消息节点、运行、事件、审核、用量和订单。Redis 用于限流与短期缓存，对象存储保存隔离上传、资产和导出。会话节点持有父节点和版本，编辑和重生成创建明确分支。检索先测 PostgreSQL 的中文、繁简、英文和专有名词召回，再评估 pgvector 或独立索引。队列与模块先共用可运维的基础设施。独立扩容需求和持久化工作流增多后，再拆分服务或引入工作流引擎。

```text
提交消息 + 幂等键 ──▶ 持久化消息、运行、额度预留
                                │
                                ▼
                       模型运行与事件序号
                                │
     手机断线 ──▶ 保存游标      ├──▶ SSE/快照 ──▶ Web、桌面、手机
                                │
停止请求 ──────────────────────▶ 唯一终态 + 账本结算
```

幂等键按账号和操作隔离，同键不同请求返回冲突。重放事件以运行 ID 与事件序号去重；游标过期用权威快照恢复。发送成功后断开订阅可重新接续，显式停止进入取消状态。自然完成、用户取消、上游超时与重复回包均用原子状态变更收敛到唯一终态和一套有效用量记录。弱网端优先接续原运行；SSE 不稳定时降级为原生流式适配或快照轮询。

维护产品模型 ID、供应商版本、工具能力与上下文预算的映射。历史会话保存当次实际模型和策略版本，模型退役时同时保留旧消息并提示后续可选模型。长上下文优先保留系统约束、当前请求和用户明确要求的材料，压缩旧轮次时记录可观测的边界。深度研究允许追加新要求，阶段快照包含输入版本、已完成工作及新的范围，副作用的旧审批随动作变化失效。

### 模型、文件和数据策略

供应商接口按文本、视觉、图片、检索、音频、嵌入和工具执行声明能力。区域内路由按能力、同意、权益、预算和数据处理边界选型。实时双向语音使用独立的媒体通道和短期凭据，支持可见录制状态、打断和撤权。固定题集回归质量、来源可查性、用量和延迟。

文件解码、索引和代码分析放在受控 Worker 中。隔离存储先校验和扫描，再向有权用户开放。运行时执行评估环境无默认外网访问，限制文件、资源和生命周期。文件、项目、个人记忆、临时会话和历史库各有明确的数据策略。删除与撤权优先阻止读取，再清理索引、缓存、附件和派生产物；对备份、依法保留及供应商副本留清理或到期证据。恢复后重放删除和撤权记录。

手动记忆按账号、工作空间及可选项目分别启用。编辑正文会保存新条目并在独立日志撤销旧标识，备份恢复时清除旧正文。历史引用、自定义指令与记忆开关分别保存，恢复时按各自撤权版本判断是否可用。生成接入时，当前对话分支仍是基本上下文。跨对话历史由独立许可控制，项目记忆由当前项目许可控制。上下文应携带最少来源标识，查询来源时重新检查权限。本地临时对话只处理单条提示，并把首批验证限定在回环环境的模拟模型。

个人分享可选择整段对话或单条回复，默认生成预览后确认的快照。组织分享可按策略限制同组织访问，并在界面标明是否随原对话更新。加锁对象按分享策略拒绝或撤回链接。继续聊天或套用任务只创建接收者的独立副本，重新评估身份、配额和连接权限。举报针对会话、分享链接、任务或公开产物记录对象及必要证据，将用户反馈与内容处置分别处理。

### 长任务、协作与扩展

事务发件箱交接任务，客户可读取阶段、日志摘要、报告与取消状态。Worker 只重试幂等步骤，关键副作用需要权限再校验、审批快照及执行标识。外部结果未知进入查证流程。调度使用任务、触发时间与事件标识去重，覆盖夏令时和暂停。用户可撤销连接器，状态变更同步影响后续读取和写入。

产物以工作空间、版本、ACL、来源和父级关系为通用模型。文档类视实际共同编辑体验评估带版本的操作日志或 CRDT。早期私有预览与产品凭据隔离，公开站点使用独立域和内容审核。实时视频、共编和本机宿主的能力单独发布。远程接续使用绑定设备、授权目录、短期会话和可撤销权限，测试仅接入自有测试设备与样例项目。

### 自测分层与验收证据

| 层级 | 测试范围 | 执行时点 |
| --- | --- | --- |
| 单元与契约 | 权限、事件解码、变更兼容、分支、引用、计划时区和状态迁移 | 每次改动 |
| 集成与故障注入 | 持久化、Worker 重启、供应商限流、回调重复、迁移、恢复和账本校验 | 合并前与发布候选 |
| 跨端端到端 | 签名包登录、输入、同步、权限、媒体、渠道支付、无障碍与升级 | 每个发布候选和支持矩阵变更 |
| 模型与产物评测 | 固定题集、来源核验、中文、文件理解、产物打开与人工复核 | 模型、提示、策略或工具升级 |
| 压力与演练 | 目标吞吐、延迟、费用、告警、灰度、熔断、回滚和备份恢复 | 各阶段发布前 |

本地与 CI 使用固定样例模型、时钟、网络故障和合成数据覆盖确定性行为。真实供应商、商店回调和推送使用授权测试环境，签名与原生权限在真机复测。用例记录阶段、需求名称、构建、设备/版本、地区、账号与套餐、操作、预期、结果、日志或截图及缺陷。未测、失败、通过和不适用分别记录，后者附能力矩阵中的依据。M0 冻结业务性能、质量、成本及恢复阈值，按目标负载采集基线。

## Risks / Trade-offs

- 区域供给或材料不可用 → 用合同、接入实测、能力矩阵和实际账单测算验证。核心能力缺供给的市场暂停发布。
- 鸿蒙桥接、浏览器后台或商店审核受限 → M0 真机验证，选原生适配并按渠道差异设置资格和入口。
- 越权、重复扣费或数据丢失 → 权限、多设备、恢复和订单并发场景作为发布阻断项，逐项复核最终数据。
- 计划成本膨胀 → 分能力计量、限额、故障降级、地域约束与评测预算，共用底层能力逐阶段发布。
- 后台框架边界直接外露 → M0 先验证登录、PostgreSQL、租户与 SSE，M1 先完成内部闭环，再铺开全端和商店联调。

## Migration Plan

先开独立开发、测试、预发布环境与隔离数据。构建签名候选包，演练数据库兼容迁移、客户端新旧版本、状态恢复及回滚。阶段发布先服务端兼容变更，再通过资格开关按租户、平台和市场启用，最后提交已验收渠道。异常时关闭受影响功能、回退兼容版本并保护账本和运行状态。恢复只对已核实的处理步骤重放，对未确定的订单和外部动作完成查证后再更新状态。

## Open Questions

- M0 确认首发市场、可采购供应商、资费、数据处理条款与上线资质。
- M0 决定鸿蒙最小支持范围、RNOH 或 ArkTS 路线、桌面 CPU/系统版本及分发方式。
- M0 根据峰值负载、试测与预算冻结支持矩阵、性能和模型质量阈值。专项能力的地区及权限边界在对应里程碑前确认。
