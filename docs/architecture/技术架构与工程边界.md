## 应用与服务

```text
桌面浏览器 / 移动浏览器 ── Next.js / React
iOS / iPadOS / Android ─── React Native / Expo
HarmonyOS NEXT ────────── RNOH 或 ArkTS / ArkUI
macOS / Windows ───────── Electron 宿主 + Web 界面
                              │
                版本化 API / 流式事件 / 媒体通道
                              │
       ┌───────── ContiNew Admin 与 AI 模块 ────────┐
       │ 身份与权限  会话与分支  项目与资产           │
       │ 权益与账单  模型网关    运行与任务           │
       └───────────────┬───────────────────┬──────┘
                       │                   │
      PostgreSQL / Redis / 对象存储    Worker / 隔离执行
                                           │
                                模型 / 搜索 / 语音 / 插件
```

所有端用同一套版本化 API、错误码、能力描述和事件契约。TypeScript 客户端共享 SDK、领域数据、设计变量和契约测试数据。ArkTS 端按同一契约维护客户端；生成器兼容性在 M0 验证。Web 与桌面可共享渲染器构建，桌面宿主独立构建。iOS、Android、鸿蒙和桌面保留分发及签名流水线。逻辑模块建议在立项后落入 `clients/{web,mobile,desktop,harmony}`、`packages/{contracts,sdk,design-tokens}`、`services/{api,worker}`、`infra` 等目录。 [Next.js](https://nextjs.org/docs/app) · [Expo](https://docs.expo.dev/faq/) · [HarmonyOS 开发](https://developer.huawei.com/consumer/en/harmonyos/develop/) · [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

`services/api` 已按 ContiNew Admin `v4.2.0` 克隆为独立后端仓库。AI 产品域使用独立业务模块，运营管理与消费者访问走分用途授权。M0 验证 PostgreSQL 迁移、上游登录初始化、租户隔离和 SSE 响应，再确定部署基线。 [后端选型与功能复审](../release/后端选型与功能复审.md)

## 会话、事件与跨端同步

- 数据模型将工作空间、项目、会话、消息节点、生成运行、事件、附件和产物分开。消息节点持有父节点标识，编辑和重新生成建立分支。设备切换依赖服务端权威状态，端侧可保存草稿、最近读取版本和运行游标。
- 发起运行时先落库，客户端携带幂等键。断线会造成客户端无法判断发送是否成功，再次提交应拿回原运行。对同一幂等键提交不同请求体时应返回冲突。允许同一聊天存在多个明确分支。
- 回复以 SSE 推送，可包含正文、引用、工具进度、产物、用量及终止状态。客户端用运行 ID 加单调递增序号去重。运行接收结束后持久化最终状态，过程事件按策略过期。游标过期时先重新取权威快照，再继续订阅。
- 本地断流和生成取消分别处理。关窗口或网络掉线后运行按服务端策略继续。按下停止时发起显式取消，取消和自然完成竞争时只提交一个终止结果。上游暂不支持立即中止时向用户反映真实状态，并按实际用量对账。
- 先测目标移动运行时和代理对流式读取、缓冲及后台冻结的实际行为。端侧可用原生流式模块或当前快照轮询降级。实时双向语音独立走 WebRTC 或供应商媒体通道，验证打断、前后台切换、麦克风撤权和回声，鸿蒙也在 M0 真机验证。 [OpenAI API Quickstart](https://developers.openai.com/api/docs/quickstart) · [WebRTC](https://webrtc.org/getting-started/overview)

## 模型、搜索和资产

- 供应商接口按文本、视觉、图片生成、嵌入、搜索、实时语音分别声明能力。路由依据地区、产品权益、用户同意、能力和预算，回退只使用同一数据处理策略允许的供应商。避免把某个供应商的会话 ID、消息格式或产品名写入领域模型。
- 用户端只取得自身会话令牌。服务端保存供应商密钥，实时端仅获取短时、最小权限的凭据。需要对比不同供应商的结构化输出、流式工具事件、中文质量、引用质量、首字延迟、错误率、保留期限和单位成本。 [开发 Quickstart](https://developers.openai.com/api/docs/quickstart) · [API 数据说明](https://developers.openai.com/api/docs/guides/your-data)
- 中国大陆版首轮比较阿里云百炼与火山方舟，分别核对所选模型的接入地域、推理范围、数据保留及实时语音能力。海外在官方支持的地区把 OpenAI API 纳入候选。两地供应商均以同一组中文、多模态和故障用例验证。供应商文档能确认接入选项，具体服务适用性需结合部署配置、合同和实际测试。 [百炼地域与部署范围](https://help.aliyun.com/zh/model-studio/regions) · [火山引擎实时音视频模型接入](https://docs.volcengine.com/docs/real-time-communication/configure-llm?lang=zh) · [OpenAI 支持地区](https://help.openai.com/en/articles/7947663-chatgpt-and-openai-api-supported-countries-and-territories)
- 对话和资产检索先验证 PostgreSQL 是否满足体量及中文召回，语义检索再评估 pgvector。中文断词、繁简、英文及专有名词以真实题集验收，达不到召回/延迟目标时评估独立检索引擎。永久记忆、项目知识、普通历史、临时聊天的读写、删除和向量索引各有规则。 [PostgreSQL 全文检索](https://www.postgresql.org/docs/current/textsearch.html) · [pgvector](https://github.com/pgvector/pgvector)
- 附件先隔离再扫描，校验类型、尺寸与权限后才进入解析及索引。用短期签名链接访问对象，撤权后拒绝新签发并处理已有访问窗口。用户删除触发对象、索引、缓存及派生产物清理，明确线上数据、备份和第三方各自的期限。协作与分享先定义受众，再分配可读、编辑、邀请等权限。

## 长任务、插件和付费动作

任务持久化为等待、运行、等待批准、完成、失败或取消，并保存阶段、产物和用量。采用持久化队列与 Worker，发布事件通过事务发件箱避免落库成功却漏掉执行。加入多步审批、长时间等待和跨进程恢复后，评估 Temporal。定时调度用运行槽位唯一键去重，明确时区、夏令时、错过时点补偿，以及撤销后对已开始任务的行为。 [Temporal 工作流](https://docs.temporal.io/workflows)

网页、上传内容和第三方文档视作不可信输入。工具授权、输入校验和副作用控制由运行层实施。代码分析用一次性隔离环境、资源上限和受控网络，跨任务清理文件和凭据。连接器启用细粒度 OAuth 权限和撤销机制。邮件、发布、购买等外部动作在界面展示对象、内容、费用和权限，由用户确认后执行。无明确结果的外部操作进入查询或人工核实，避免盲目重试。 [Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter) · [插件](https://learn.chatgpt.com/docs/plugins)

权益和计费由服务端交易账本确认。商店回调统一校验、去重并定期对账，单独处理待支付、续订、撤销、退款和恢复购买。用量先保留额度再按实际结算，失败、取消和供应商切换都有记录。租户权限、内容访问审计、供应商故障切换、限流、降级和回滚纳入同一运行观测体系。
