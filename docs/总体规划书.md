# 多端 AI 助手总体规划书

探索稿 · 2026 年 11 月 22 日 · 面向产品、研发和发布负责人

## 产品目标

建设一个拥有自有名称、视觉和交互表达的 AI 助手。以 ChatGPT 公开可观察的用户任务为功能对标基线，覆盖桌面和移动 Web、iOS/iPadOS、Android、HarmonyOS NEXT、macOS 和 Windows。用户换设备后，可以继续同一段对话、打开有权访问的文件、使用同一个项目并查看任务进度。首发重心是跨端聊天，完整路线还包括多模态、研究、协作、自动化和企业治理。

功能等价按用户任务验收。每项功能写明参考日期、地区、套餐、设备、前置权限、关键步骤、结果和失败行为。地区限定和灰度功能保留独立条目。模型输出用固定题集、质量阈值和人工评审对比。界面使用自有品牌、图标、文案和设计系统。能力目录覆盖本轮公开资料中的主要产品域，逐条验收基线还需补齐账号和设备实测。 [ChatGPT 功能概览](https://help.openai.com/en/articles/9260256-chatgpt-capabilities-overview) · [套餐](https://chatgpt.com/pricing/) · [更新记录](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) · [下载页](https://chatgpt.com/download/)

## 项目边界

AI 助手拥有独立项目根目录。前期参考 Guard Find 的 Expo、React Native 和鸿蒙构建经验，以及后台 Web 的流式聊天交互。AI 助手的身份、会话、工作空间、计费、数据和部署均在本工程内独立管理。

ContiNew Admin 后端位于 `services/api`，以正式标签 `v4.2.0` 为基线。OpenSpec 维护跨端账号、会话、消息流到高级功能的实施顺序，先验证后端和首条跨端旅程，再按功能域验收发布。 [后端选型与功能复审](release/后端选型与功能复审.md)

## 平台与技术决策

| 平台 | 建议 | 关键约束 |
| --- | --- | --- |
| 桌面及移动 Web | Next.js、React、TypeScript | 响应式和键盘操作。验证弱网、移动浏览器后台、中文输入法、文件和媒体权限 |
| iOS、iPadOS、Android | React Native、Expo development builds | 共享导航、业务状态和协议。麦克风、推送、商店支付和扩展走平台适配 |
| HarmonyOS NEXT | 使用现有 RNOH 经验验证可行性，ArkTS、ArkUI 作为独立实现的预案 | 验证 DevEco 构建和签名、中文输入、音频、推送、文件、支付。关键依赖失败时保持同一后端契约，切换实现 |
| macOS、Windows | Electron，复用 Web 聊天界面 | 应用快捷键、托盘、安全存储、签名和更新由桌面宿主管理。独立验证系统权限、商店与不同 CPU 架构 |
| Linux | 后续评估，首发提供浏览器入口 | 根据用户需求、实际安装分发和系统集成测试排期 |
| 微信小程序 | 可选渠道 | 先明确业务目标及平台审核、组件和接口限制，再承诺功能 |

Expo 作为 iOS 和 Android 主线，Web 使用独立框架处理桌面布局、复杂编辑器及浏览器能力。对比过 Expo Web 全复用和客户端分开的方向，选择共享协议、设计变量、测试数据和业务规则，界面实现按平台优化。Electron 作为桌面主选，Tauri 可在安装体积或内存有严格预算时评估，实际取舍看系统 WebView 渲染、音视频和团队维护成本。鸿蒙以 NEXT 真机结论确定 RNOH 或原生路线。 [Expo FAQ](https://docs.expo.dev/faq/) · [Expo Web](https://docs.expo.dev/workflow/web/) · [Next.js App Router](https://nextjs.org/docs/app) · [HarmonyOS 开发](https://developer.huawei.com/consumer/en/harmonyos/develop/) · [Electron](https://www.electronjs.org/docs/latest) · [Tauri](https://v2.tauri.app/start/)

后端采用 ContiNew Admin（Java、Spring Boot）作为多模块底座，在新业务模块中实现独立的 AI 服务，运营后台与消费者 API 分用途授权。目标数据库 PostgreSQL 保存产品数据和运行账本，先验证上游 Liquibase 的 PostgreSQL 配置及迁移。对象存储保存文件及产物，Redis 支撑限流和短期缓存。模型工具通过供应商接口接入，持久化队列及 Worker 接管后台任务，复杂工作流按实测再评估工作流引擎。 [ContiNew Admin v4.2.0](https://github.com/continew-org/continew-admin/releases/tag/v4.2.0) · [后端选型与功能复审](release/后端选型与功能复审.md)

## 里程碑

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| M0 可行性 | 首发地区和供应商候选、样例题集、后端启动与 PostgreSQL 迁移、跨端设备矩阵、鸿蒙/桌面签名验证、预算模型 | 目标市场与供应商可用性有证据。后端及真机关键能力已验证或选定可行预案。产品、质量和预算基线达成一致 |
| M1 跨端聊天 | 登录、历史、流式对话、停止/重试、编辑分支、基本搜索、删除/导出、套餐和用量基础 | Web、iOS、Android 完成主流程内测。鸿蒙、macOS、Windows 接入同一测试环境并走完主流程。各端可分批提交审核 |
| M2 工具与多模态 | 联网引用、文件/图片/音频输入、图像生成编辑、数据分析、语音、项目、记忆和分享 | 引用可定位，隔离执行与删除复核通过。真机权限和降级行为通过。鸿蒙和桌面可按能力矩阵发布 |
| M3 研究与协作 | 深度研究、长任务、提醒、定制助手、插件授权、协作文档/表格/幻灯片、交互展示、网站发布 | 任务可恢复，支持取消和审批。产物权限、版本回退、计划任务去重和用户可见进度均通过 |
| M4 扩展产品域 | 企业治理、代码工作台、远程接续、主动助手、购物/钱包、健康/财务等能力 | 各域单独通过质量、数据与授权审查。交易和敏感数据能力按目标市场独立决策 |

用预估日活、峰值并发、每用户活跃天数、请求数、输入输出量、媒体分钟、工具调用量、沙箱分钟和保留天数推导容量及 COGS。模型成本按真实样本的 P50/P95 用量与供应商报价测算，计入重试、工具和退款。团队至少需要明确客户端、后端与模型编排、发布测试、运维安全和产品设计的责任人。工期和人员成本在 M0 拿到真机结果、目标负载和预算后估算。

## 方案审查结论

主体架构能支撑逐步扩大范围。最早能推翻方案的三项是目标地区的模型采购与数据处理边界、HarmonyOS NEXT 真机能力，以及跨端断流后仍能去重恢复的会话契约。审查因此把三项移到 M0 或 M1 退出条件，并为每项设置可验证的失败场景。完整目录保留后续阶段，首发以关键旅程和上架条件闭环。实机、压力、供应商评测与地区法律审查要在实施阶段取得证据后才可作上线判断。 [发布与反向审查](release/验收与风险审查.md)
