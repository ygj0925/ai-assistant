# 本地候选版本与运行手册

本地验收基线是青屿助手 0.1.0。后端来自独立的 ContiNew Admin v4.2.0 工作树，验收构建使用 JDK 21.0.10。Web 使用生产 Next.js 构建，移动验收使用 Pixel Tablet API 36 调试环境，桌面使用 Electron 45.4.1 Windows x64 本地包。功能资格由 `/api/assistant/v1/capabilities` 随当前会话和工作空间返回。[独立后端基线](../../qa/m0-backend-baseline.md) · [各端验证入口](../../qa/verify.md)

本地媒体组合验收记录了 Next.js 构建 ID、构建清单及实际 Java 模块的 SHA-256。该环境执行 166 到 170 的 PostgreSQL 增量迁移，通过七项 Chrome 用例。Android 录音验收同时保存调试 APK 摘要、原生权限结果和经扫描的精确 WAV。 [Web 与后端构建核对](../../qa/verify-results/combined-media-chrome-2026-11-24/build-witness.json) · [Android 调试包摘要](../../qa/verify-results/project-recording-android-2026-11-24/debug-apk.sha256)

## 运行与更新

1. 为候选版本记录独立后端提交、包摘要、迁移计数、客户端构建和测试环境。用隔离 PostgreSQL、Redis、对象存储和适用的扫描配置启动。保管部署凭据与独立删除日志，测试夹具使用单独账号及存储命名空间。 [本地启动与验证](../../infra/local/README.md)
2. 发布前用相同迁移重复启动；核对本次执行数量和初始种子。升级和恢复验证各自保存日志、备份前状态以及恢复后的 HTTP 断言。恢复数据库后以原绑定日志重放，确认已撤销访问、存量合法对照和账本状态，再开放写入。 [双数据库验证](../../qa/m0-backend-baseline.md) · [独立日志恢复](../../qa/assistant-erasure.md)
3. 使用合成会话做登录、首条流式回复、停止、恢复和历史自测。再验证组织策略、分享撤回、文件授权与受影响的独立功能。API 开关关闭的能力只有在资格和数据依赖验证后才可对目标用户开放。 [回归入口](../../qa/verify.md)
4. 值班先确认模型供给、队列延迟、过期租约、供应商故障率和账本差异。用运行标识及时间范围关联日志、队列和账本，按权限控制点处置。若发现越权或错误结算，关闭受影响能力或暂停流量，保留复现证据并走已演练的恢复路径。 [指标与告警](../../qa/assistant-observability.md) · [故障演练](../../qa/assistant-resilience.md)
5. 回退须保留执行当前组织策略和读取独立删除日志的后端版本。分享和记忆开关的关闭与重新开启已经过同包复测，撤权后的数据保持不可访问。早于监护日志格式的包在隔离只读副本拒绝启动，八张表的摘要、日志和账本副本保持原样。组织策略编辑可单独关闭，仍须验证已有模型与连接器限制。 [组合恢复与旧版验证](../../qa/assistant-composite-recovery.md) · [组织策略关闭和恢复](../../qa/assistant-organization-policies.md)

恢复历史数据库时，在开放消费者流量前确认还原库身份和当前备份。在已迁移的隔离还原库先使备份内的普通设备会话和组织 SSO 会话失效，再用同一个独立权限日志启动当前后端。普通用户重新登录后恢复对话与权益访问，组织 SSO 仍需满足当前目录绑定和关联同意。日常重启、滚动升级及沿用当前数据库的版本回退使用原有会话策略。 [恢复后再登录验收](../../qa/assistant-composite-recovery.md#还原后重新认证)

## 客服排障

| 现象 | 核对内容 |
| --- | --- |
| 登录或工作空间访问被拒绝 | 核对当前账号、选定组织、成员资格及设备会话。用权限状态验证后续访问。 |
| 对话中断或重试结果未知 | 请保留运行标识与发生时间。查看现有运行、事件游标和唯一终态，再核对实际用量。 |
| 组织没有可选模型或连接器 | 请组织所有者检查当前模型列表、连接器策略与是否需要重新审核。更换工作空间后刷新资格。 |
| 私有文件或网页无法打开 | 核对扫描结果、当前工作空间、已确认版本及撤回状态。下载授权绑定当前设备、短时有效且只可使用一次。公开站点撤回后按新请求验证地址。 |
| 购买或退款状态不一致 | 核对渠道、订单及权益状态。使用账本与渠道确认结果对账，待核实订单保留现有状态。 |

## 上线门槛

本地验证适用于工程回归和隔离演示。正式上线需先确认市场和模型等供应组合、目标阈值、负责人、团队控制的后端远端版本和生产等价环境。各渠道须取得对应签名包、真机升级测试、隐私资料、计费验收和审核状态。分批开放依据指定构建的可复验证据，当前逐项进度以 OpenSpec 为准。[任务与外部依赖](../../openspec/changes/build-cross-platform-ai-assistant/tasks.md) · [发布风险](验收与风险审查.md)
