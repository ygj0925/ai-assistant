# 后端选型与功能复审

复审日期为 2026 年 11 月 22 日。以目标用户任务及数据结果验收 ChatGPT 的公开功能，自有产品按平台、地区、套餐、年龄和组织授权开放。此处的优先级对应 [OpenSpec 实施清单](../../openspec/changes/build-cross-platform-ai-assistant/tasks.md)。

## 后端基线

| 项目 | 结论 |
| --- | --- |
| 上游仓库 | [continew-org/continew-admin](https://github.com/continew-org/continew-admin) |
| 后端工作树 | [ai-assistant-api](https://github.com/ygj0925/ai-assistant-api)，可以检出到 `services/api`，也可以作为相邻的子模块 |
| 基线 | `v4.2.0`，提交 `6c6724e4444268b81e27442abb93252d3bfc2bd6`，本地分支 `codex/ai-assistant-backend` |
| 运行基础 | Java 17、Spring Boot 3.5、Maven 多模块。正式标签作为起点，开发分支的后续修复逐项审查 |
| 可复用 | 运行入口、后台账号及 RBAC、行级多租户、Redis、文件与日志、Liquibase 迁移约定 |
| AI 产品开发 | 消费者账号和权限、会话流和恢复、模型供应商、额度与订单、记忆、任务、协作及工具运行 |

上游采用 Apache-2.0，业务扩展保留授权及归因。正式标签带有 PostgreSQL SQL，但主 Liquibase 配置默认启用 MySQL。M0 需要用选定 PostgreSQL 和 Redis 跑通空库、迁移、启动、管理和消费者登录，再确认框架可作为目标环境底座。还应验证默认租户、上下文初始化和 RSA 登录路径。开发分支有相关修复，是否适用于本地标签以复现结果为依据。 [正式标签](https://github.com/continew-org/continew-admin/releases/tag/v4.2.0) · [上游后续 RSA 修复](https://github.com/continew-org/continew-admin/commit/64c0dc28c300a858f0f2f0f55dfca1766c8ee2ee)

当前标签的 Maven 配置排除了依赖数据库和 Redis 的应用上下文测试。启动验收因此单独使用隔离实例、独立凭据和端口，记录数据库迁移与实际登录结果。

## 复审结果与自测

| 阶段 | 原计划的缺口 | 已加到规划的验收 |
| --- | --- | --- |
| M0/M1 | 管理系统作为底座后，后台权限和租户头的边界需要显式验证 | 管理和消费者令牌分用途，检查路由、工作空间成员、SSE 重连、缓存和 Worker。普通用户输错或变更租户选择时，仍只能访问有权资源 |
| M1 | 多端和上架渠道并行过早，基础体验失败会造成多端返工 | Web 与首个移动端先通过登录、断流换设备接续和权限验证，再扩大客户端发布验证。最终范围仍覆盖全部目标端 |
| M1 | 列出了模型选择与回退，缺少模型退役、长上下文及历史接续 | 用旧会话接续用例验证历史可读、实际版本可查、后续模型选择明确，兼顾质量、费用和延迟。 [ChatGPT 模型说明](https://help.openai.com/en/articles/20001354-gpt-6-and-other-models-in-chatgpt) |
| M1 | 普通好评、差评与举报处置缺少不同的工作流 | 从回复开始建立用户举报、运营审计及处置。分享和任务上线后复用同一举报链路。 [ChatGPT 举报入口](https://help.openai.com/en/articles/10245791-reporting-content-in-chatgpt-and-openai-platforms) |
| M2 | 分享写得过于笼统，可能意外暴露会话附件或后续消息 | 区分整段与单条回复、个人快照与组织受限分享，预览实际内容和受众。验证链接撤销与接收人独立副本的语义。 [ChatGPT 对话和任务分享](https://help.openai.com/en/articles/7925741-sharing-conversations-and-scheduled-tasks-in-chatgpt) |
| M2 | 记忆有开关和删除，但缺少来源展示与授权变化的联测 | 支持的场景展示来源，测试临时对话、个人记忆、项目资料及检索不会因权限变化而串用。 [ChatGPT 记忆](https://help.openai.com/en/articles/8590148-memory-in-chatgpt) · [临时聊天](https://help.openai.com/en/articles/8914046-temporary-chat-in-chatgpt) |
| M2 | 听写与通话已列入，但没有定义实时转写与发送前编辑 | 用同一段中文语音在受支持端验证转写进度、纠错、权限撤回和最终发送内容。 [ChatGPT 听写](https://help.openai.com/en/articles/12168547-voice-dictation-faq) · [实时听写发布记录](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) |
| M3 | 研究可取消和恢复，缺少运行中追加约束 | 以追加来源限制为用例，保留可复用的阶段进度，重新核对变动动作的审批。 [ChatGPT 更新记录](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) |
| M3 | 有定时与事件触发，缺少分享与接收人套用 | 任务副本使用接收者的配额、连接及权限。验收凭据、记忆、历史产物和上传文件不随任务复制。 [ChatGPT 对话和任务分享](https://help.openai.com/en/articles/7925741-sharing-conversations-and-scheduled-tasks-in-chatgpt) |
| 范围修正 | 原 M3 将群聊作为当前对标功能之一 | ChatGPT 自 2026 年 7 月 9 日起逐步退出群聊，新建和加入已停止。当前路线保留项目与产物协作，群聊归历史能力。 [群聊退役说明](https://help.openai.com/en/articles/12703475-retiring-group-chats-in-chatgpt) |

## 后续产品决策

- 账号冷启动可评估导入其他产品的授权历史或偏好。先确认数据格式、去重、上传隔离和预览。官方的账号间对话转移依赖导出后上传文件，而桌面代理导入有单独的设置、项目和权限范围。这两类流程需要分开标记。 [ChatGPT 数据导出](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data) · [从其他代理导入](https://learn.chatgpt.com/docs/import)
- M0 逐端登记系统分享入口、通知、快捷键、麦克风和屏幕采集差异。桌面窗口上下文和浏览器扩展各有权限与渠道要求，先明确范围和平台支持，再决定排期。灰度功能按实际账号和平台记录。 [Appshots](https://learn.chatgpt.com/docs/appshots?surface=app) · [浏览器扩展](https://learn.chatgpt.com/docs/chrome-extension)
- 后端独立仓库使用给定的上游远端，本地分支用于产品开发。团队需要共享时再决定自有远端及父仓锁定方式，并在 CI 中验证两套仓库的版本一致性。
