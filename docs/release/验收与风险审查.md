# 验收与风险审查

## 发布前先验证的事项

| 可能推翻方案的条件 | 如何验证 | 核验失败的处理 |
| --- | --- | --- |
| 中国大陆缺少足够稳定、获准使用的模型和搜索供应 | 核对目标用户、服务主体、地区支持、合同、数据处理、报价、供应稳定性及实际质量。分别测试中文、多模态和工具场景 | 切换为经确认可用的供应组合，按市场关闭受影响能力。核心聊天无可行供应时，暂缓该市场发布 |
| 鸿蒙跨端框架能构建，但核心能力无法稳定交付 | 在 NEXT 真机测试签名安装、输入法、流恢复、上传、录音权限、推送和支付，至少覆盖最低支持版本及主流设备 | 为失败能力选定原生桥或 ArkTS/ArkUI 实现，按能力矩阵更新发布范围 |
| 流式消息切换设备后重复或丢失 | 复现提交超时、重复点击、弱网重连、App 重启、并发停止、旧游标和双设备编辑 | 以持久化运行、幂等键、事件序号和权威快照重构边界。该主流程为 M1 阻断项 |
| 未授权用户仍能读取共享、已删或跨租户内容 | 对比正常会话、临时聊天、项目记忆、分享链接、对象存储和索引。覆盖删除、撤权、登录切换、选错租户和备份恢复后的重放 | 阻断发布，修权限和清理链路，再做端到端验证 |
| 搜索或模型能操纵工具，或者长任务重复发起外部动作 | 用不可信网页和文件、重复 webhook、Worker 崩溃及结果未知场景检验授权、审批和对账 | 阻断相应工具。副作用结果未知时进入查证流程，保留用户可见记录 |
| 订阅和退款使端侧权益不一致 | 用商店沙箱验证续订、恢复购买、退款、撤销、账号切换和迟到回调。覆盖不同渠道的审核路径 | 调整地区渠道配置及对账流程，冻结该渠道发布直至权益恢复可验证 |
| 成本或模型故障耗尽容量 | 用真实请求组合压测文本、图片、语音和研究，模拟上游限流、故障及重试风暴，按高分位测算单用户与全局成本 | 分能力限流，设置预算和可解释降级。符合地区及数据策略才允许模型回退 |
| 桌面或移动分发无法持续 | M0 做打包签名验证，M1 验证升级回退、权限清单、支付路径、隐私信息及注销入口 | 保留已验证的渠道及 Web 入口，按平台修正后再提交 |

## 目标市场与合规核查

OpenAI 公布 ChatGPT 与 API 的支持地区。中国大陆未列入本轮查询的官方支持清单，应把在大陆具备合适区域、服务资格、数据条款和运行能力的供应商作为该市场的接入基础。全球部署按地区分配供应商、存储、内容政策和功能开关，逐市场核对采购和数据流。 [OpenAI 支持地区](https://help.openai.com/en/articles/7947663-chatgpt-and-openai-api-supported-countries-and-territories)

中国大陆版拟公开提供服务时，按实际服务形态核查备案或登记、安全评估、生成合成内容标识、个人信息保护、未成年人保护及跨境处理的适用性。模型供应商与应用运营方的责任应逐项明确。健康、金融、支付和面向未成年人的产品域须走独立的市场、数据与发布审查。其他地区也按各自数据、消费者和内容要求核查。 [生成式 AI 服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm) · [2026 年 9 至 10 月备案与登记公告](https://www.cac.gov.cn/2026-11/20/c_1796918603542950.htm) · [生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

商店规则按应用、地区和发行方式校验。发布前确认数字订阅、恢复与退款渠道、隐私说明、数据安全表单、权限提示、应用内账号删除路径，以及签名、升级和上架要求。iOS、Google Play、AppGallery 和其他安卓渠道各自准备提交证据。 [Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/) · [Apple 注销要求](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion/) · [Google Play 支付](https://support.google.com/googleplay/android-developer/answer/9858738) · [华为应用提交](https://developer.huawei.com/consumer/cn/doc/doccenter-submission/50104/) · [华为应用内支付](https://developer.huawei.com/consumer/cn/doc/harmonyOS-guides/store-iap-config-agc/)

## 可检查的发布门槛

- **跨端功能。** 核心旅程用真实发行包验证。覆盖桌面/移动浏览器、iPhone/iPad、代表性 Android 与鸿蒙设备、macOS 与 Windows 桌面。检查中文输入法、缩放、屏幕阅读器、高对比、键盘和签名升级。
- **数据与权限。** 执行两个账号、两个租户、成员撤权、分享撤销、删除和备份恢复用例。核心越权、错误计费和数据丢失的严重缺陷清零。明确删除时限、恢复点目标和恢复时间目标，并通过恢复演练。
- **质量与性能。** 为每个任务族固定对标题、实测账号和版本，度量任务通过率、引用正确率、中文质量、首字延迟、错误率、语音打断延迟和成本。M0 按代表性场景和预期负载冻结目标，M1 起对照目标压测及做回归。使用同一批任务做供应商切换前后比较，并人工复核高风险样本。
- **运行及发布。** 从端到运行、工具和账本可用关联标识追踪，日志按最少必要记录。完成灰度、兼容版本、数据库迁移、熔断、回滚、应急预案和客服手册演练。已知的平台差异进入发布说明及客服能力表。
- **交付证据。** 每项功能附带对应验收用例、适用地区、平台、系统版本、套餐、实测人、实测日期和结果。代码或配置上线与验收通过分别记录。

## 反向审查记录

已用现有仓库、官方功能开放差异和故障场景走查。方案由此作了五项修正。

1. 功能基线按平台、地区、套餐和灰度维护，HarmonyOS NEXT 使用自有产品验收矩阵。
2. 鸿蒙可行性和 RNOH/ArkTS 决策进入 M0，桌面签名和升级也提前验证。
3. 客户端断线、请求重复、用户取消和上游完成定义为独立事件，加入跨端恢复与计费验收。
4. 附件授权、检索索引、记忆和分享链接分别纳入撤权与删除验收，明确备份和第三方边界。
5. 将模型供给、商店权益及带副作用的工具作为独立发布判断，限制供应商切换和自动重试。

上述初审已用于实施。上线范围由指定候选包、目标阈值及对应市场和渠道验收决定。
